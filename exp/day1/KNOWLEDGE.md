# 背景知识速成（给第一次真机实验的组员）

> 面向不熟悉具身智能的同学。每节控制在 3 分钟能读懂。更深的资料见仓库 `literature/`。

## 1. 具身智能是怎么工作的

机器人控制是一个**闭环**：每秒若干次重复「看 → 想 → 动」。

```
观测 (图像/关节角/里程计) ──▶ 策略 (模型/程序) ──▶ 动作 (关节角/速度) ──▶ 世界变化 ──┐
        ▲                                                                            │
        └────────────────────────────────────────────────────────────────────────────┘
```

- **观测 (observation)**：相机图像、深度图、关节角度、底盘里程计、IMU 等。
- **动作 (action)**：往执行器下发的目标值——关节角度、末端位姿、夹爪开度、底盘速度。
- **控制频率**：闭环每秒跑几次。SDK 限 200 Hz；相机流通常 30 Hz 左右。**两者速度不匹配时要用最新一帧、动作做插值**，这是真机工程的基本功。
- 策略可以是神经网络（VLA），也可以是普通程序（状态机 + 规则）。**课程允许任何路线，评分只看现场表现**。

## 2. 我们的方案：三段式架构与模块分工

中期报告定的架构：

```
指令(颜色+体积) → 状态机(编排+异常处理) → 技能层:
                     ├─ 感知技能: 颜色识别/瓶子定位/液面读数
                     ├─ VLA: 抓取、转运、归位等短时操作
                     └─ 专用倾倒控制器: 分次倾倒 + 视觉闭环
```

四个模块及彼此依赖（对应中期报告的分工，后天真机实验各阶段正好按模块各自主导）：

| 模块 | 负责人 | 职责 | 后天实验最相关的部分 |
| --- | --- | --- | --- |
| 感知与液面读数 | 吕佳恒 | 颜色识别、瓶子定位、量筒刻度标定、体积估计与读数可靠性 | 阶段 2 相机采图、阶段 4 量筒标定 |
| 抓取 / 转运 / 归位 | 李文桢 | VLA 子任务与动作适配、抓瓶与持瓶复核 | 阶段 3 冒烟测试（机械臂 / 夹爪） |
| 定量倾倒控制 | 张恩同 | 分次倾倒闭环、回正提前量标定、瓶口对准补偿 | 阶段 3（腰身 / 头部）+ 标定数据 |
| 状态机与系统集成 | 王健豪 | 状态机编排、异常处理、SDK 封装、底盘工作位、全流程联调 | 全部阶段 + 状态导出 / 冒烟脚本 |

- **状态机是骨架**：维护当前状态（找瓶 → 抓取 → 转运 → 对准 → 倾倒 → 读数 → 归位），检查完成条件，决定下一步；失败时有限重试或暂停。所有技能都通过 SDK 封装层执行——**SDK 封装是集成的基础设施，每个人写业务代码都会用到**。
- **为什么用状态机包 VLA**：VLA 擅长"短时操作"，但不可靠、不可解释；状态机负责"何时调用、何时停、失败怎么办"。这个组合是 2025-2026 年真机比赛的主流打法。
- **倾倒（评分大头）不用 VLA**：分次倒 + 读液面 + 回正 + 再读，用经典闭环控制比模型可靠得多，也更容易在 3 次测试里稳定发挥。
- **模块间接口**（集成前先定好）：感知输出目标位姿与体积读数；抓取模块输出"抓稳"确认；倾倒模块输出"达标 / 失败"；状态机据此推进状态。

## 3. VLA 与 wall-x（为什么暂时跑不了）

- **VLA (Vision-Language-Action)**：输入图像 + 文字指令，直接输出动作的神经网络。Wall-OSS-0.5 是自变量开源的 4B VLA（Qwen2.5-VL-3B 骨干）。
- 推理链路：GPU 机器上跑 `wall-x` 的 serving（WebSocket 端口 32195），真机端把观测发过去、拿回动作块（action chunk，一次预测未来 32 步），再经 SDK 执行。
- **组里的瓶颈**：推理约需 24 GB 显存，组内暂无 GPU（中期报告已写明）。所以当前策略是**传统规划/规则路线保底**，VLA 作为可选增强——后天真机实验完全不需要 GPU，SDK + 相机就够了。
- 数据采集的意义：遥操作录的 rosbag 可转 LeRobot 格式，将来有 GPU 时用于微调 VLA。今天先不采。

## 4. SDK 工作原理（后天真机的主角）

- SDK 是一个 **gRPC 客户端库**（`x2robot` Python 包），连到机器人内部 PC 的 SDK 服务（默认端口 50051）。注意：**它不是 ROS2 接口**，是厂商自研的 RPC 接口；消息类型长得像 ROS2（`sensor_msgs/JointState` 等），但走 gRPC。
- 连接方式：`connect("x2://<机器人IP>:50051")`，返回 `robot` 对象，一切功能挂在它上面：
  - `robot.left_arm / right_arm`：机械臂（关节角/末端位姿）
  - `robot.left_gripper / right_gripper`：夹爪（开度 0~4.5）
  - `robot.lift`：腰身升降（0~0.78 m）
  - `robot.head`：头部云台（俯仰/偏航，单位**度**）
  - `robot.chassis`：差速底盘（位置/速度模式）
  - `robot.head_camera / left_arm_camera / right_arm_camera`：相机
  - `robot.imu / radar / ultrasonic / tof`：传感器
- **控制前必须切模式**（官方示例的标准三步）：
  1. `system.set_work_mode(SDK)` —— 把整机从遥操作/数采模式切到 SDK 模式；
  2. `robot_control.set_manipulator_control_mode(JOINT_POSITIONS)` —— 机械臂用关节角还是末端位姿控制；
  3. 底盘另有 `set_control_mode(GLOBAL / RELATIVE / VELOCITY)`。
- 返回的 `ExecutionResult` 要检查 `.is_success`，失败时看 `.error_message`。

## 5. 关节空间 vs 笛卡尔空间（两种控制机械臂的方式）

- **关节空间**：直接给 6 个关节的目标角度（rad）。简单、不会出不可达解，但"让末端往上 10cm"要自己换算。冒烟测试就用这个。
- **笛卡尔空间**：给末端（夹爪）在空间中的目标位姿 (x, y, z, 四元数)，机器人内部求**逆运动学 (IK)** 算出关节角。写业务逻辑更直观（"移动到瓶子上方 10cm 处"），但可能无解/奇异。
- **轨迹与插值**：`set_joint_positions` 一次给一个目标点。想让动作平滑，要自己在两点间插值、按 200~500 Hz 连续下发（官方示例用 TOPP-RA 库做时间最优插值）。初期先用小步长 + 睡眠，够用。
- 六轴限位（rad，务必记牢）：下限 `[-2.792, 0, -3.14, -1.57, -1.4, -1.745]`，上限 `[2.792, 3.44, 0, 1.57, 1.4, 1.745]`。**超限的指令会被拒或报错，下发前自己先夹紧（clip）**。

## 6. 坐标系与位姿（真机最容易踩的坑）

- 常见坐标系：`map`（地图，建图后才有）、`odom`（里程计，开机即原点）、机器人本体 `base`、各臂基座、末端 `tool`、各相机。
- SDK 里读到的末端位姿是相对哪个系的、底盘坐标是 map 还是 odom，**第一天用 `01_dump_state.py` 实测核对**（移动已知距离看读数变化）。
- **位姿 = 位置 (x,y,z) + 姿态**。姿态常用**四元数** (x, y, z, w)，不是欧拉角——四元数没有万向锁、插值方便，但人读不懂，需要时用库转（`scipy.spatial.transform.Rotation`）。
- 正负号约定：关节正方向、底盘 yaw 正方向，第一天用小动作实测（`03_smoke_test.py` 就是干这个的），记进笔记。**宁可先动 1cm 验证方向，不要上来就大动作**。

## 7. 安全概念

- **急停**：机身背后顶部红色按钮 + 无线急停。拍下后须关机、拉起、重启才能恢复。专人负责。
- **限位/碰撞**：关节限位见上；SDK 有碰撞检测错误码（`COLLISION_DETECTED`）。动作前用相机/肉眼确认路径无障碍。
- **液体**：水洒到机器人电子部件 = 事故。倒液功能只在方案成熟后测，且底盘与托盘间保持距离、用抹布垫底。
- 电量 <20%、异响、发热 → 停。

## 8. 评分规则 ↔ 技术决策（为什么这么设计实验）

单次测试 80 分 = 颜色 20 + 体积 30 + 过程 30（抓瓶 7 + 转运 7 + 倒液 9 + 归位 7），3 次取平均 + 报告 20 = 100。

关键推论：

1. **体积 30 分是大头，且只有 5% 误差才满分**。所以量筒液面读数（凹液面下缘）的精度是生命线 → 今天标定采图是最高优先级。
2. **洒漏不扣分**——但"只以量筒内液体计分"，洒了不影响判分（注意：过程分的"完成倒液"仍要达成）。这放宽了控制难度：可以分多次小量倒，每次回正读数，宁可慢不可过。
3. **取错颜色 = 颜色 0 分 + 体积 0 分，只剩过程分**。颜色识别必须可靠——绿/蓝/黄/红四个纯色，用 HSV 阈值就够稳，比上模型靠谱。
4. **卡死 60 秒判失败**：状态机必须带看门狗——任何技能超时（如 15 s）就回安全姿态重试或跳过，绝不原地死等。
5. 单次不限时长：策略上**慢就是快**，分次倒 + 读数 + 微调，比一次倒准更可控。

## 9. 几个当天会遇到的术语

| 术语 | 意思 |
| --- | --- |
| rosbag | 机器人端录制的数据包（遥操作采集），保存在 `/home/xr/bagfiles/bags` |
| LeRobot | HuggingFace 的机器人数据集/训练格式，wall-x 训练吃的就是它 |
| gRPC | 远程过程调用框架，SDK 的通信层；端口 50051 |
| homing / reset | 机械臂回零位；头部回中位 |
| 里程计 (odometry) | 底盘对自身移动的估计，会随打滑漂移 |
| 凹液面下缘 | 量筒读数规则：液面凹陷的最低点，裁判按它计分 |
| 余流 | 回正后瓶口残余液体继续滴入量筒，会造成超量——倾倒控制器要留提前量 |
